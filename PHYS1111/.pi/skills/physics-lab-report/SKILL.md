# 物理实验报告

## 任务约定

报告使用用户本次实测数据。历史报告用于学习组织方式、版式和有依据的方法，不能提供本次读数、实验现象、操作经历或学生身份信息。

默认制作实验后的“数据处理报告”，模仿历史报告中自然、直接的学生语言，写清测量数据、计算过程、不确定度和实验结论。不额外堆砌封面、目录、摘要和大段实验原理。若用户要求完整报告或当次课程另有要求，再补充必要的目的、仪器、原理和方法。

必须交付 LaTeX 源文件。环境具备条件时编译 PDF 并逐页检查。最后三个正文板块固定为：**实验结论 → 误差分析 → 思考题**。附加资料和计算日志另存，不在思考题后增加正文板块。

## 开始时读取

1. 读取工作区文档、已有记忆、用户最新要求及教师批注。
2. 查找本次数据、对应实验介绍、空白记录表、课程绪论，以及同实验历史报告。搜索时注意被 Git 忽略的历史资料目录，必要时使用 `fd -H -I`。
3. 阅读 [不确定度与拟合规范](references/uncertainty.md)，决定本次计算口径。
4. 在 PHYS1111 工作区读取 [课程资料索引](references/course-map.md)，只加载本次实验需要的介绍与历史原件。
5. 首次制作或更换历史材料时读取 [历史材料蒸馏记录](references/distillation.md)。检查历史方法能否用于本次装置和数据，不凭“优秀报告”标签认定正确。
6. 交付前逐项执行 [交付检查](references/acceptance.md)。

以上相对路径均相对于本 Skill 目录。参考文件不替代当次讲义。

## 工作流程

### 1. 把输入转成可以核对的数据

- 识别实验名称、实际完成的任务、实验组别、测量次数、单位、仪器型号/分度值/允许误差、零点修正、温度、计时计数含义、参考量来源。
- 图片或扫描 PDF：先转录，再对照原图逐项核查，重点看正负号、小数点、单位和零差。无法辨认的数字不能猜。
- PDF 文本抽取可能漏掉公式、图片表格；遇到缺失或乱码，渲染对应页读取。不能把抽取失败写成原报告缺项。
- 表格数据读取实际单元格，公式和缓存结果都要核查；不能直接相信 Excel 缓存或复制旧公式。只用足够的工具，不为一个表格搭建通用导入框架。
- 保留原始读数与修正后数据两层，保留原始精度，不用历史数据补空，不从期望答案反推数据。
- 一次性测量也要列出不确定度依据。缺少仪器信息时先查当次讲义/手册，仍缺少再集中向用户询问。
- 可继续处理已知部分；关键数据未齐时，生成明确标为草稿的结果，列出缺项和影响，不把估算伪装成最终测量结果。

在实验目录建立简短的 `计算说明.md`：数据来源、单位解释、仪器依据、采用的不确定度口径、讲义题目页码、未解决事项。此文件用于复核，不把工作日志塞入提交报告。

### 2. 从物理模型建立计算关系

先写“原始读数 → 修正量 → 平均值/拟合参数 → 最终物理量”的依赖关系，逐个确定单位、符号、适用条件和不确定度来源。明确共用零点、标尺、参考物和校准参数产生的相关性。

- 从实验原理推导结果，不照抄历史符号。拟合横纵轴反转后，斜率及其单位也改变。
- 计时显示为 `2T`、`10T`、半周期或脉冲计数时，先核对实际模式；精确整数换算同时作用于数值和不确定度。
- 先做单位统一、量纲与数量级核验，再算数值。半径/直径、g/kg、mm/m、mV/V 单独核对。
- 检查弹性范围、小角度、匀速下落、雷诺数、热平衡、相同换热条件等。只有数据允许时才作相应结论。

### 3. 计算并保留可复现记录

按本实验写简短、线性的 `calculate.py`，或沿用已有可信计算脚本。按需使用 Python 标准库、NumPy/SciPy；工作区新增依赖优先由 pixi 管理。无需搭建通用计算引擎，不写测试套件。

- 脚本直接读取本次结构化数据，输出统计量、拟合参数、残差、不确定度预算和结果；保留足够有效位，最后统一修约。
- 图、表、正文结果来自同一份计算结果。适合时由脚本写出 `results.tex` 和绘图数据，避免手动重复录入。
- 统计与剔除规则应用于未舍入数据；报告原始样本数、保留样本数及处理依据。
- 中间量和最终量均计算适用的不确定度；精确常数、计数、纯定义量不强行虚构不确定度。确需忽略某项时给出量级或预算依据。
- 每种方法给一组完整示范：公式、必要代入、单位、结果及不确定度；其余同类组表格汇总，不机械复制多页相同运算。
- 最终结果必须有数值、单位、不确定度及概率/覆盖因子说明。参考偏差另列，不能替代不确定度。

### 4. 撰写报告

读者就是本课程的教师和学生。正文直接使用已核实的课程约定，不把常规实验作业写成方法审查、标准辨析或计算审计报告。

- 沿用历史报告简洁的表达方式，如“测得……”“取……”“代入得……”“由……准则，剔除……”“因此……”。学习语言和组织，不继承错误算法、虚构经历或他人数据。
- 不写“根据操作手册”“实验介绍中给出”“按课程简化口径”等来源与流程交代。直接写仪器误差、参考值、公式和所取概率；来源页码及计算口径放在 `计算说明.md`。
- 不为默认课程做法额外解释为什么选这一套体系、标准或数值。课程和用户已经确认的参数直接使用，不重复询问或声明。真正影响结果且无法从资料确定的缺项才需澄清。
- 不反复写“仅包含……”“不代表……”“不能证明……”“本次没有测量……”等防御性声明，也不替读者提出作业未要求的问题。超出证据的结论直接不写；确实影响结果理解的特殊条件在相关位置简短说明一次。
- 保留完成作业所需的公式、代表性代入、单位、剔除依据、各级不确定度和最终结果。无需为常用概念另立定义或增加符号；思考题明确要求定义时正常作答。
- 默认不展示完整灵敏系数表、相关性讨论和逐项预算。计算仍应正确完整，详细记录放在脚本、机器输出或 `计算说明.md`；只有教师要求或解释结果确有需要时才放进正文。
- 结论直接回答测出了什么、结果是多少、观察到什么关系。误差分析围绕装置与操作，用简短自然的段落说明影响及改进，不机械铺陈每一种潜在风险。

表达示例：

| 避免 | 改为 |
|---|---|
| 根据操作手册，秒表仪器误差明确规定为0.01 s | 秒表仪器误差为0.01 s |
| 按课程简化口径，采用双侧95%的系数 | 取置信概率P=0.95 |
| 实验介绍中给出铜的参考比热容…… | 以铜为标准，c_Cu=…… |
| 本报告仅进行一次筛查，不根据预期答案删点 | 第2次读数超出判别上限，予以剔除 |
| 本次只有一个温区，不能验证完整冷却规律 | 写实际测得的冷却时间和比热容，不另加此句 |

按实验实际内容组织数据处理板块，例如一次性测量、零差与直径、加卸载拟合、最终物理量及不确定度。标题编号自动生成。

末尾固定为：

**实验结论**：回答实验目的，列出每组/每种方法最终结果及不确定度，概括实验得到的物理关系。任务要求参考比较或理论验证时，完成相应比较；验证应考虑差值及其不确定度，不凭“相近”宣布成功。不要在结尾追加与作业无关的适用范围声明或未做事项。

**误差分析**：根据计算判断主要误差来源，结合装置说明它怎样影响结果以及如何改进。能确定方向时说明偏大或偏小；需要条件时用“若……则……”自然表达。未经记录的气泡、碰壁、录像计时等不得写成亲历事实，也不逐项追加“现有记录无法确定”之类声明。重复测量不能消除固定偏差。

**思考题**：全文检索实验介绍中的“思考题”“作为思考题”“选做”等，保留题号、原题及选择规则，逐题作答。需要补做实验的题目区分理论方案与实测结果，不能捏造数据；没有独立题目的讲义不得自行编题充数，可说明“本次实验介绍未列独立思考题”。来源、页码放在计算说明中，正文不必反复标记。

### 5. 排版与编译

以 [LaTeX 模板](assets/report-template.tex) 为起点；若本次有更匹配的历史报告，学习其数据排列和标题层级，保留用户指定的简洁风格。

- 中文、A4、约 12pt 正文；居中实验标题和身份行，简短页眉、页码；不要沿用历史作者姓名学号。
- 默认黑白。区分组别优先用点型、实虚线、空心/实心；确需彩色时优先深蓝和深红，并保持灰度打印可辨。
- 表格使用可编辑 LaTeX，列头标单位，避免彩色底纹、Excel 截图和不必要的密集框线。确有助于对应课程记录表时可保留简单网格。
- 图使用 PGFPlots 或矢量 PDF，轴标题有物理量和单位，拟合线与测量点分开；误差棒说明代表标准还是扩展不确定度。没有可信不确定度时不能编造误差棒。
- 默认显示与结论有关的斜率、截距、参数不确定度及拟合质量；不整块粘贴 Excel 的 F 值等无关统计输出。
- 保持图内字号可读，不把整张表缩到极小；长表拆分或使用 longtable。不给所有浮动体强加 `[H]`，避免大块空白。
- 检查运行系统和现有字体，不在 WSL 中硬编码 `fontset=windows`。模板采用 TeX 自带 Fandol 字体。
- 若有 XeLaTeX，在报告目录执行两遍 `xelatex -interaction=nonstopmode -halt-on-error report.tex`；使用现有 pixi 环境时加其真实运行前缀。也可使用支持该模板的 Tectonic。保存编译日志，修复错误、缺字、未定义引用及明显溢出。
- 用 `pdftoppm` 或可用 PDF 渲染工具逐页查看，核对页底、表头、公式、单位、图例、分页。成功编译不等于版式合格。

### 6. 交付与记录

通常保留：报告 `.tex`、所有被引用资源、核验后的 `.pdf`、原始/转录数据、`calculate.py`、必要的机器输出及 `计算说明.md`。中间编译文件、页面预览放 `build/`，不要散落在报告目录。若用户仅要 `.tex`，遵循其交付范围，但仍尽可能完成编译检查。

最终告知源文件/PDF位置、采用的计算口径、实际核验范围和剩余缺项。编译失败或未做逐页检查要如实说明，不能宣称“可直接提交”。不自动修改用户已完成的其他报告。
